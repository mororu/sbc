# Admin portal routes (Epic 3)

Every `/admin` route except `/admin/login` is guarded in `src/hooks.server.ts` (AD-10, Story 3.1): no page checks the session alone, and an unauthenticated request is redirected to sign-in before any route code runs.

- `login/`: the sign-in form (no shell, its own 560 px column).
- `logout/+server.ts`: POST only; ends the session.
- `(portal)/`: every signed-in page. `+layout.*` is the admin shell (header, nav with the call and reply badges); `+page.*` is the admin home (worker warning, flags, "Anrufliste" with the call list, "Antworten" with the reply reminders, next bookings); `+error.svelte` is the admin 404 inside the shell.
- `(portal)/day/+page.server.ts`: `/admin/day` redirects to the default day (Story 3.2).
- `(portal)/day/[date]/`: the bookings of one day, with that day's open reply reminders at the top (Story 3.4); an unknown or malformed date is an admin 404.
- `replyDone` action on `(portal)/` and `(portal)/day/[date]/` (Story 3.4, shared `#lib/server/reply-action.ts`): posts `bookingId` to `markReplyDone`, the only writer of `reply_done_at`: `{ done: true }`, `fail(409, { code: 'already_done', bookingId })` for `conflict`/`not_found`, `fail(503, { code: 'failed', bookingId })` on a lock timeout, an admin 404 for a missing or malformed id.
- `called` action on `(portal)/` (Story 3.6, `#lib/server/call-action.ts`): posts `bookingId` and the shown `notice` token to `markCalled`, the only command writing `last_told_notice` and `resolved_at`: `{ called: true, bookingId, firstName }`, `fail(409, { code: 'already_done' })` for `conflict`/`not_found`/`past`, `fail(409, { code: 'stale', bookingId })`, `fail(503, { code: 'failed', bookingId })` on a lock timeout, an admin 404 for a missing or malformed id. Every payload carries `action: 'called'`, so the home tells its results from `replyDone`'s.
- `(portal)/booking/[id]/`: a live booking's detail with "Buchung löschen" and the impact dialog (Story 3.3), or "Diese Buchung gibt es nicht mehr." for a deleted one; an unknown or malformed id is an admin 404. Its `delete` action posts the impact token to `deleteBooking`: 303 to the booking's day, or `fail(409 | 410 | 503, { code })` for `stale`/`past`, `not_found` and a lock timeout.
- `(portal)/blocks/`: the upcoming blocks with "Block löschen" and the impact dialog per row, "Neuer Block", and the status from `?saved` / `?deleted`, removed from the address after hydration (Story 3.5). Deleting needs JavaScript: the button appears after hydration (accepted as in 3.3). Its `delete` action posts `blockId` and `impactToken` to `deleteBlock`: 303 to `/admin/blocks?deleted`, or `fail(409 | 410 | 503, { code, blockId })` for `stale`/`past`, `not_found` and a lock timeout; a missing or malformed id is an admin 404.
- `(portal)/blocks/new/`: the block form (Story 3.5). `check` validates with the shared schema plus `toBlockInstants` (a time the spring clock change skips is `block_time_missing`) and runs `getBlockCheck`: `fail(400, { errors, values })`, `fail(409, { errors: { start: 'block_past' } | refusal, values })`, else `{ values, dialog }`. `save` posts the values and the token to `createBlock`: 303 to `/admin/blocks?saved`, `fail(409, { code: 'stale', dialog, values })`, the past error or refusal (409), or `fail(503, { code: 'failed', values })`.
- `(portal)/settings/`: the settings cards (Story 3.7). Actions `hours`, `changeover`, `horizon`, `instructions`, `contact` parse their card with `parseSettingsCard` and write through `changeSettings`; `preheatCheck` answers `{ card, saved: true }` for an unchanged window, else `{ card, values, dialog }`; `preheat` posts the window and the token: `{ card, saved: true }` or `fail(409, { card, code: 'stale', dialog })`; `password` hashes outside the transaction and calls `changeAdminPassword` (keeps the own session, deletes the others; if the own session is already gone, the cookie is cleared and a 303 goes to sign-in with `expired=1`). Invalid fields are `fail(400, { card, errors, values })` (never the password), a lock timeout `fail(503, { card, code: 'failed' })`. Story 3.8 adds Saison and Schlüsselbox-Code cards to the same page.

New admin pages go under `(portal)/`. Nav hrefs live in `src/lib/admin-nav.ts`. Reads go through `#lib/server/db/queries`, writes through `#lib/server/commands`. Row ids and guest data appear only here, and guest data only in `mailto:`/`tel:` links.
