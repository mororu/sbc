- (decision) [ADOPTED] Paradigm: functional core, imperative shell + transactional outbox (user). Pure domain module computes start times, heat state, arrival time, notice, affected booking, heat change from (bookings, blocks, settings, now) - no DB/mail/clock access. Every mutation (book, delete booking, create/delete block, settings change, mark called, mark done) goes through one command layer that writes the change, recomputes the affected booking and enqueues outbox rows in the same DB transaction. One background worker drains the outbox (settle delay debounce, re-check at send, keybox at T-24h, catch-up after downtime). Prevents divergent per-route heat/notification logic and lost emails. Rejected: logic in routes; Redis/job framework
