### Architecture delta

- **Lint is clean and there are no cycles**, but the layer table is not what lint enforces.
- **Mail imports more than the table allows.** Mail may import i18n, time (display), env and transport only, but:
  - it imports `#lib/domain`: `mail/confirmation.ts:6`, `keybox.ts:6`, `heat-change.ts:8`;
  - it imports the view model `booked-view.ts` (`confirmation.ts:9`, `keybox.ts:9`), which imports `db/queries`, so mail reaches the database transitively;
  - it uses `#lib/time` for logic, not display: `heat-change.ts:10`, `confirmation.ts:8`.
- **`db/queries` imports `#lib/domain`** (`queries/outbox.ts:5`, `booking.ts:4`, `setting.ts:3`). This was already the case in Epic 1.
- **Lint does not stop routes from importing worker-only queries.** For example, `getSendData` selects the guest email and `getKeyboxSettings` returns the code; both are re-exported from `queries/index.ts`, whose header says guest queries never select contact columns.
- **Rules computed outside the core (AD-1):** the outbox policy is in `commands/outbox.ts`:
  - confirmation-first gating, `L194-223`;
  - the sweep order, `L162-187`;
  - the recheck and cancel branches, `L226-246`;
  - the supersede rules, `L107-140, 311-314`.

  `getHeldKeyboxRows` (`queries/outbox.ts:67-81`) re-implements the claim filter.
- Disposition: add lint rules for mail and queries, and keep worker-only queries out of routes (B4). Reconcile the layer table (S1, carried over).

## Behavior verification

The email flows were run on `main` at `f92fb3c`, on a dev server with a scratch database and the local sink, using four `DEV_NOW` instants (12 Jan 09:00Z, 09:15Z, 17:05Z, 20:05Z). Bookings went through curl POSTs with tokens from the form, and 17 emails landed in the sink. Logs, the database and helper scripts are in the session scratchpad.

1. **Confirmation: pass.**
   - One confirmation row and one keybox row per booking.
   - Correct headers: From, Reply-To = the admin contact, `Content-Language`, `Auto-Submitted`.
   - The format is multipart text and HTML, `lang`, color-scheme, no images.
   - DE and EN subjects and bodies per the epic, including "folgt gleich" past the cutoff, with the snapshot frozen.
2. **Keybox email: pass.**
   - It waits until the cutoff, then sends with the current notice and updates `last_told_notice`.
   - A booking made after the cutoff gets a row due now. With the code unset it is held and logged once, and goes out when the code is set.
   - "Code: 4 7 1 1" stands first.
   - A missing EN instruction text holds the EN rows.
   - A changed code resends nothing.
   - Observation: the HTML has two `<h1>`.
3. **Heat-change emails: pass.**
   - Each change upserts one row due now + 10 min, sent with the right variant: good news, urgent new arrival time, urgent hot → cold (collapsed).
   - `last_told_notice` updates.
   - The hot → cold case had to be faked in the database, since only Epic 3 deletion can make a booking colder.
4. **Refused sends: pass, simulated.**
   - A booking with its email set to NULL gives a keybox row `refused` with reason `no_address`.
   - `callList(getSendProblemRows(now))` returns `keybox_refused` for it, and `keybox_overdue` for a held row past its clamp. That entry clears once the row is sent.
5. **Heartbeat and log: pass.**
   - `beat_at` updates every tick.
   - The logs hold only the row id, kind, attempt, state and SMTP code: no names, emails, mobiles or codes.

**Not exercised:**
- real SMTP; 4xx/5xx refusals and backoff;
- a stale in-flight release;
- a settle-delay reset;
- a heat change after the keybox email;
- expiry at the start;
- soft-delete cancellation;
- the browser booking flow (curl only).

Fixture bookings create no outbox rows.
